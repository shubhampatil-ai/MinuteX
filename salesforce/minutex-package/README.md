# MinuteX — Salesforce package source

The source of the installable **MinuteX** package: a customer installs it,
logs MinuteX in as their integration user, and is done — no Salesforce Site,
no copied code, no pasted secret.

This folder is self-contained. `salesforce/minutex-starter/` (the hand-built
receiver of the setup guide) is the older path; once the package ships it can
be deleted without touching this folder.

## What's in it

| Folder | Contents |
|---|---|
| `applications/`, `tabs/` | The **MinuteX** app in the App Launcher, with the **MinuteX Meetings** and **MinuteX Setup** tabs |
| `lwc/minutexSetup` | The **MinuteX Setup** page: connection status; a list of the objects meetings can link to (any object, custom ones too), one summary line each; Edit opens one object: the main-record switch and a choice for each output (Never / Off / On / Always). Each object says what it still needs: where its meetings show, whether tasks can attach (Allow Activities), whether the integration user can read it |
| `lwc/minutexRecordMeetings` | The **MinuteX Meetings** component for any record page: that record's meetings, newest first, main record flagged. Found by the record id every Meeting Link stores, so **no lookup field is needed for any object** |
| `classes/` | `MinuteXReceiver` (the REST API MinuteX calls), `MinuteXMeetingSync` (what one meeting event writes), `MinuteXSetupController` (the Setup page), `MinuteXRecordMeetings` (the MinuteX Meetings component), `MinuteXDeliveryLog`, and their tests |
| `objects/` | MinuteX Meeting, MinuteX Participant, MinuteX Meeting Link (one row per linked record → the "MinuteX Meetings" related list), MinuteX Linkable Object (the Setup page's choices), MinuteX Delivery Log (what was delivered and how it went; 90 days), MinuteX Webhook Settings (**protected**: the signing secret), and three Task fields |
| `layouts/` | The MinuteX Meeting page (Participants, Linked Records, Delivery Log) |
| `customPermissions/` | **MinuteX Integration** (may set the signing secret) and **MinuteX Admin** (may save the Setup page) |
| `permissionsets/` | **MinuteX Integration**, **MinuteX Admin** and **MinuteX Meeting Viewer**, generated by `scripts/generate_permission_sets.py` from the field files; re-run it after adding a field or object |

## How it differs from the starter

- **No demo objects.** No Property / Site Visit; MinuteX links meetings to
  Leads, Contacts, Accounts and Opportunities.
- **The signing secret is set by MinuteX, not pasted.** The settings are
  protected (customer admins can't read them). Right after its Salesforce
  login, MinuteX calls `POST …/minutex/v2/setup/secret` — the one call that
  isn't signed, allowed only for a signed-in, non-guest user with the
  MinuteX Integration custom permission. The secret it replaces stays valid
  as the previous one.
- **Namespace-safe.** Lookups use field tokens, not field names, so the code
  is right with or without the package namespace. Once packaged, the REST
  path is `/services/apexrest/<namespace>/minutex/v2`; `setup/secret`
  answers with the namespace so MinuteX can tell.
- **Showing meetings on records.** A package can't edit a customer's pages or
  create fields, so the admin places the **MinuteX Meetings** component on
  each record page that should show meetings (one drag in Lightning App
  Builder). It works on any object without a lookup field. Lead, Contact,
  Account and Opportunity also have packaged lookups, so the classic
  "MinuteX Meeting Links" related list works on their page layouts too.

## Validate (any time, no namespace needed)

```bash
cd salesforce/minutex-package
sf org create scratch --target-dev-hub minutex-target --definition-file config/project-scratch-def.json \
  --alias minutex-pkg-test --duration-days 1 --wait 15
sf project deploy start -o minutex-pkg-test -d force-app --test-level RunLocalTests --wait 30
sf org delete scratch -o minutex-pkg-test --no-prompt
```

Last run (2026-10-08): 55 components, 35/35 tests, coverage MinuteXReceiver
91 %, MinuteXMeetingSync 93 % (a managed release needs 75 %).

## The managed package

- **Namespace:** `DevMinuteX` (linked to the Dev Hub `minutex-target` on 2026-10-12; permanent once a version is released).
- **Package:** `MinuteX`, type Managed, id `0HogL0000004iTtSAI` (alias in `sfdx-project.json`).
- Beta versions install only in sandboxes, scratch orgs and Developer Edition orgs. Nothing is locked until a version is promoted.

## Make it a managed package (once the namespace is linked to the Dev Hub)

1. Put the namespace in `sfdx-project.json` (`"namespace": "<ns>"`).
2. Create the package (once):
   `sf package create --name "MinuteX" --package-type Managed --path force-app -v minutex-target`
3. A beta version, installable in sandboxes, scratch and Developer Edition orgs:
   `sf package version create -p "MinuteX" -x -c --wait 30 -v minutex-target`
4. When the objects and fields are final — **a released managed package
   locks its schema** — promote: `sf package version promote -p 04t…`
5. Install link: `https://login.salesforce.com/packaging/installPackage.apexp?p0=04t…`

## The login app (External Client App "MinuteX")

MinuteX signs in to Salesforce through the External Client App **MinuteX**, shipped in the package (from 0.1.0.5):

| Where | What |
| --- | --- |
| `externalClientApps/MinuteX.eca-meta.xml` | The app itself, `distributionState` Packaged |
| `extlClntAppOauthSettings/MinuteX_oauth.ecaOauth-meta.xml` | Scopes (Basic, Api, RefreshToken) and the `oauthLink` to the global settings |
| Dev Hub `minutex-target` only | The global OAuth settings (consumer key, callback `…/salesforce/oauth/callback`, PKCE required, secret optional, refresh-token rotation) and the org policies. Not packageable; `.forceignore` keeps them out, never commit them. |

Every customer org shares the same consumer key, so the server's `SF_OAUTH_CLIENT_ID` is one value. A customer **installs the package first, then taps Connect**: the login app exists in their org only once the package is installed.

To change the callback or OAuth flags, retrieve `ExtlClntAppGlobalOauthSettings` from `minutex-target`, edit, and deploy it back there. No new package version is needed.
